# 🗓️ 勤務表自動生成システム（看護師・介護士向け）

Streamlit + SQLite + Google OR-Tools（CP-SAT）で作られた、
病棟・施設向けのシフト自動作成アプリです。

## できること

- 職員（看護師・介護士）のマスター管理（雇用形態、夜勤可否、月間労働時間上限など）
- 入社年月日から、労働基準法第39条に基づく有給休暇の法定付与日数を自動計算
- 曜日別・シフト区分別の必要人数設定（入浴日など特別対応日の人数増にも対応）
- 夜勤の柔軟配置（介護士が不足する日は、看護師での代替を許可する設定が可能）
- 月またぎ夜勤（前月末日が夜勤だった職員の考慮）
- Google OR-Tools（CP-SAT）による自動シフト生成
  - **絶対に守るルール**：夜勤翌日の休み、月またぎ夜勤の考慮、施設が設定した連続勤務上限、
    **週1日以上の休日確保（労働基準法第35条）**、パート等の月間時間上限、
    個人の希望休み・有給希望・希望勤務の反映、介護士不足時の看護師代替
  - **できるだけ叶える目標**：夜勤回数の平準化、土日勤務の偏り軽減
- 生成結果をExcel形式（集計列付き）でダウンロード

## ⚠️ 重要な注意

このアプリが自動生成するシフト表は、あくまで「たたき台」です。
最終的な勤務表としての適法性・妥当性は、必ず施設の管理者・社会保険労務士等の
専門家が確認したうえで確定させてください。

「連続勤務日数の上限」は、労働基準法が直接定める絶対ルールではなく、
施設ごとの運用ルールとして設定・変更できる項目です（デフォルトは4日）。
労働基準法上の絶対ルールは「週1日、または4週で4日」の休日確保であり、
このアプリでは「7日間の中で必ず1日以上の休日を確保する」という、より安全側の
実装で法律要件を満たしています。

## セットアップ手順（ローカルで動かす場合）

### 1. 必要なもの
- Python 3.10以降

### 2. インストール

```bash
# 仮想環境を作る（任意ですが推奨）
python -m venv venv
source venv/bin/activate   # Windowsの場合は venv\Scripts\activate

# 必要なライブラリをインストール
pip install -r requirements.txt
```

### 3. 起動

```bash
streamlit run app.py
```

ブラウザで `http://localhost:8501` が自動的に開きます。

初回起動時は、動作確認用のサンプル職員データ（看護師20名・介護士20名）が
自動的に登録されます。不要であれば「職員登録・一覧」タブから削除してください。

## GitHubへのアップロード手順

1. GitHubで新しいリポジトリを作成する（例: `shift-schedule-app`）
2. 以下の3つのファイルをリポジトリのルート（一番上の階層）に置く
   - `app.py`
   - `requirements.txt`
   - `README.md`（このファイル）
3. GitHubのWeb画面から直接アップロードする場合：
   - リポジトリのページで「Add file」→「Upload files」
   - 3つのファイルをドラッグ＆ドロップ
   - 「Commit changes」を押して保存

## Streamlit Community Cloud への公開手順（無料・Vercelは使いません）

このアプリは常時動き続けるPythonプロセスが必要なため、Vercel（サーバーレス向け）
ではなく、Streamlit公式の無料ホスティングサービス「Streamlit Community Cloud」を使います。

1. [https://share.streamlit.io](https://share.streamlit.io) にアクセスし、GitHubアカウントでログイン
2. 「New app」を押す
3. 「Repository」で先ほどのGitHubリポジトリを選択
4. 「Branch」は `main`、「Main file path」は `app.py` を指定
5. 「Deploy」を押す
6. 数分待つと、`https://your-app-name.streamlit.app` のようなURLでアプリが公開される

公開されたURLを、ケアラボの「管理職ツール」から開くリンクとして設定すれば、
アプリ内から直接シフト表アプリを開けるようになります。

### ⚠️ データの永続化について

Streamlit Community Cloudは、アプリの再デプロイ時にファイルシステムがリセットされ、
`shift_app.db`（SQLiteファイル）の中身が消えてしまうことがあります。

試作・動作確認の段階ではこのままで問題ありませんが、実際の運用を始める際は、
外部の永続的なデータベース（例：Supabaseの無料プランなど）に接続方法を
切り替えることを強くおすすめします。

## ファイル構成

```
shift-schedule-app/
├── app.py             # メインプログラム（本体はこの1ファイル）
├── requirements.txt   # 必要ライブラリ一覧
├── README.md          # このファイル
└── shift_app.db        # 実行すると自動生成されるデータベースファイル（Git管理は不要）
```

`.gitignore` に `shift_app.db` を追加しておくと、データベースファイルを
誤ってGitHubにアップロードせずに済みます。
